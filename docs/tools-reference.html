tools/ — Running & Reviewing Reference

Exact commands, environments, inputs/outputs, and how to review each tool's results. Companion to docs/ocr-correction-architecture-built.html (the why); this is the how. Every command below is copy-pasteable against the pilot book, المومياوات ناشيونال جيوجرافيك-lighton.

Two Python environments in play
This repo's dependencies (fitz/PyMuPDF, google-genai, faster-whisper) live in a conda env, not system Python. Tools that only touch local JSON files run fine with plain python3; anything calling Gemini or doing audio alignment needs: 
.venv/bin/python3 tools/<script>.py ...
Each tool below says which one it needs.
0. run_full_pipeline.py — the one-command orchestrator The full chain, in order 1. ensemble_review.py — detect disagreements 2. vlm_arbiter.py — resolve disagreements visually 3. apply_corrections.py — write word-level fixes 4. replace_page.py — replace a failed page wholesale 5. context_detector.py — catch errors both engines agreed on 6. build_context_review.py — browsable HTML for those findings 7. apply_context_suggestions.py — apply accepted suggestions 8. build_review.py — original-vs-corrected comparison page Reminder: build_reader.py picks up everything automatically

0run_full_pipeline.py

Runs steps 1-6 below in one command — both OCR engines, detection, arbitration, corrections, re-synthesis, correlated-error detection — then stops cleanly at the one deliberately-manual review step (step 7). Everything after that point still needs the individual commands below.

vx2lm env GEMINI_API_KEY + OPENROUTER_API_KEY 
VX2=.venv/bin/python3

# the whole book
$VX2 tools/run_full_pipeline.py "assets/PDF Samples/<book>.pdf"

# scoped to the first N pages -- same convention as main.py's --pages
$VX2 tools/run_full_pipeline.py "assets/PDF Samples/<book>.pdf" --pages 2

# an explicit page range
$VX2 tools/run_full_pipeline.py "assets/PDF Samples/<book>.pdf" --pages 11:15

# page 13 to the end
$VX2 tools/run_full_pipeline.py "assets/PDF Samples/<book>.pdf" --pages 13:
RequiresNothing pre-existing for a fresh book — it does the whole Gemini-then-LightOn-then-rename dance itself (see step 1's note on why that dance exists at all).
WritesEverything steps 1-6 individually write, in sequence.
ResumableYes, at every level — a quota wall on any internal step just means re-running this same command later; already-finished work (including a book whose work/<book>-lighton already exists) is detected and skipped.
--pages only scopes what gets freshly OCR'd, not the whole run
It's passed straight through to both OCR passes. Every later step just operates on whatever pages already exist on disk for that book -- so on a book with prior work, --pages 2 won't shrink an already-larger ensemble_review.json down to 2 pages, it only limits what's freshly fetched this run. For a truly isolated N-page run, delete work/<book> and work/<book>-lighton first.

How to review

Its own console output narrates each of the 8 steps as it runs, and prints the exact next commands (steps 7 onward) when it stops. Same review guidance as steps 1-6 below apply to whatever it produced.

→The full chain, in order

Gemini OCR of the same PDF → ensemble_review.py → vlm_arbiter.py → apply_corrections.py + replace_page.py → re-diacritize + re-TTS → context_detector.py → build_context_review.py → (human review) → apply_context_suggestions.py → re-diacritize + re-TTS → build_reader.py (or build_review.py for a side-by-side view)

run_full_pipeline.py (step 0 above) runs everything up through build_context_review.py in one command, then stops for the human review step. Steps 1-2 and 5-6 each write a JSON report first, then a separate step applies it — nothing ever writes to pXXX.json without a distinct, previewable file existing first.

1ensemble_review.py

Diffs LightOn's OCR against a Gemini OCR of the same PDF, page by page. Produces ensemble_review.json — the file every other tool in this chain reads.

plain python3 no API key 
python3 tools/ensemble_review.py \
  "work/المومياوات ناشيونال جيوجرافيك" \
  "work/المومياوات ناشيونال جيوجرافيك-lighton"
RequiresBoth dirs must already have pXXX.json page records (i.e. both OCR engines have run on this PDF).
Writes<lighton_dir>/ensemble_review.json
ResumableYes — re-running only computes pages not already in the file. An existing page's entries (including any VERIFIED verdicts from step 2) are left untouched.

How to review

Open the JSON and check summary.flagged / summary.tokens for the overall disagreement rate. Per page, action is KEEP (both engines agree) or FLAG (disagree, or one engine produced nothing). A `FLAG` entry whose `id` starts with gemini-only: means LightOn produced no token there at all.

Don't re-run this carelessly on a book you've already arbitrated
It IS safe now (resumable since this session), but always confirm you're pointing at the right lighton_dir — this file is the single source every later tool depends on.

2vlm_arbiter.py

For every page with a FLAG, sends the real page image + the disagreeing candidates to Gemini vision, one call per page. Writes verified_txt back into ensemble_review.json and upgrades action to VERIFIED.

vx2lm env GEMINI_API_KEY 
# needs the conda env (google-genai)
.venv/bin/python3 tools/vlm_arbiter.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json"
Requiresensemble_review.json must exist (step 1). Reads its recorded gemini_dir to find the page images itself.
WritesUpdates the same ensemble_review.json in place (adds verified_txt, flips action).
ResumableYes — writes after every page, not just at the end. Re-running only processes pages that still have a FLAG; anything already VERIFIED is skipped.

How to review

For each VERIFIED entry, compare lighton_txt / gemini_txt / verified_txt. Most will match one of the two originals; a genuinely new third answer is worth a second look before trusting it (numeric/ISBN-style content especially).

Real constraint: gemini-3.6-flash's daily free-tier cap is 20 requests/day
A 429 mid-run is expected on an active project, not a bug. Just re-run the same command later — it resumes exactly where it stopped.

3apply_corrections.py

Writes VERIFIED corrections into the actual pXXX.json token records. The first tool in this chain that touches pipeline data, not just a report.

plain python3 no API key 
python3 tools/apply_corrections.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json"
RequiresAt least one VERIFIED entry (i.e. step 2 has run).
WritesUpdates affected pXXX.json files: substitutes txt (keeping the old value in ocr_txt), deletes a token outright if verified_txt=="", resets status to "extracted".
Never doesInsert a word LightOn never produced (a gemini-only id) — reports these grouped by page instead. See step 4 for the case where that's most of a page.

How to review

Its own console output is the review: N corrected, M deleted, across P pages, plus a per-page breakdown of skipped gemini-only words. No separate file to open.

Then re-run downstream stages for touched pages

.venv/bin/python3 -c "
import sys; sys.path.insert(0,'src')
from pipeline import run_tashkel, run_speak_gemini, build_reader
from pathlib import Path
d = Path('work/المومياوات ناشيونال جيوجرافيك-lighton')
run_tashkel.run(d)
run_speak_gemini.run(d, run_speak_gemini.VOICE)
build_reader.build(d)
"

4replace_page.py

For a page LightOn didn't misread a few words on, but failed almost entirely on. Wholesale-swaps that page's token list for Gemini's (same schema on both sides).

plain python3 no API key 
# auto-detect and replace any page >=50% gemini-only
python3 tools/replace_page.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json"

# or target one page explicitly
python3 tools/replace_page.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json" --page 16

# or change the auto-detect threshold
python3 tools/replace_page.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json" --threshold 0.7
WritesReplaces tokens, box_level, and ocr_engine in the target pXXX.json; records the original engine in ocr_engine_replaced_from; resets status to "extracted".
Side effectThe page's LightOn ids are gone — tokens now carry Gemini's ids. Later tools that pair "original vs. corrected" by id (like build_review.py) detect this via ocr_engine_replaced_from and fall back accordingly.

How to review

Console prints which page(s) qualified and how many tokens were replaced. Worth opening the actual page image once (<gemini_dir>/pages/pXXX.jpg) to sanity-check the page really was a genuine failure, not a threshold false-positive.

Same re-run step as above applies afterward (diacritize/TTS/reader).

5context_detector.py

Catches the one blind spot nothing else covers: LightOn and Gemini agreeing on the same wrong word. Runs on every page's KEEP entries — not just flagged pages — using a text-only LLM as a linguistic plausibility check.

plain python3 OPENROUTER_API_KEY 
python3 tools/context_detector.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/ensemble_review.json"
Modeldeepseek/deepseek-v4-pro-0813 via OpenRouter — a reasoning model, deliberately kept off Gemini so a Gemini quota day doesn't block this layer too.
WritesA separate file, <lighton_dir>/context_review.json — never touches ensemble_review.json. Also creates/extends context_decisions.json, a template defaulting every new suspicion to "reject".
ResumableYes, per-page, same pattern as step 2.
Per-page latency varies a lot — this is expected, not a hang
Because it's a reasoning model, a page with many agreed-upon words to check can take several minutes of real "thinking" time, not seconds. Don't assume it's stuck under ~8 minutes on a large page.

How to review

Don't read the raw JSON directly — build the browsable HTML view first (step 6 below), which shows every flagged word next to the real page image.

6build_context_review.py

A browsable HTML review page for context_review.json's findings — grouped by page with the real page image inline, a suspicion-sorted jump list at the top, and every entry tagged "different word" (check the image — a real correlated-error candidate) or "case-ending" (often just the diacritizer, more debatable). Writes nothing; pure review aid.

plain python3 no API key 
python3 tools/build_context_review.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/context_review.json"
open "work/المومياوات ناشيونال جيوجرافيك-lighton/context_review.html"
Requirescontext_review.json (step 5); reads the sibling ensemble_review.json to locate page images, and context_decisions.json if it exists yet (to show current accept/reject state).
Writes<lighton_dir>/context_review.html only — never touches any JSON.

How to review — this is the one manual step in the whole chain

  1. Open the HTML this just built. Use the suspicion-sorted jump list at the top to triage, prioritizing "different word" tags.
  2. For each entry you agree with, open context_decisions.json and change its value from "reject" to "accept" (use the proposed word) — or to any other literal string to use your own correction instead.
  3. Leave everything else as "reject". Nothing is applied until step 7 runs. Re-run this tool afterward to see your decisions reflected in the page.
A pattern worth knowing before you accept things
Many flagged words are case-ending (i'rab) corrections rather than letter-level misreadings — this layer also catches the automated diacritizer's own errors (~6.6% DER), since it runs on already-diacritized text. That's exactly what the "case-ending" tag flags, so you don't have to work it out per entry.

7apply_context_suggestions.py

Applies only what you explicitly accepted in context_decisions.json. Nothing here is automatic — this is the gate between an LLM's linguistic guess and the actual pipeline data.

plain python3 no API key 
python3 tools/apply_context_suggestions.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton/context_review.json"
Requirescontext_decisions.json next to the review file, with at least one non-"reject" value.
WritesSame reversible pattern as step 3: ocr_txt preserved, "context-llm" appended to fixes[], status reset to "extracted".
Safety checkIf a token's current txt no longer matches the ocr_word recorded when it was flagged (something else touched it since), that entry is skipped and reported rather than blindly overwritten.

How to review

Console prints N tokens corrected, M skipped (changed since detection). Same re-run step (diacritize/TTS/reader) applies afterward if N > 0.

8build_review.py

A separate, one-off side-by-side page for a specific page range — original-OCR audio vs. corrected audio, inline strikethrough-correction pairs, color-coded image boxes. Not part of the normal reader; built for manually auditing a slice of a book in depth.

vx2lm env GEMINI_API_KEY 
.venv/bin/python3 tools/build_review.py \
  "work/المومياوات ناشيونال جيوجرافيك-lighton" --pages 15:19
Requiresensemble_review.json, and every page in the range must be status: "spoken" already.
Writes<work_dir>/review_<start>-<end>.html plus new audio in <work_dir>/review_audio/ (only the original-OCR track — the corrected track reuses the book's existing audio, no re-synthesis).
SkipsAny page with no comparison data in ensemble_review.json (Gemini never OCR'd it) — reported by name, not shown as a blank page.

How to review

Open the generated HTML in a browser. Page selector across the top; per page, the image with color-coded boxes (amber = VLM-verified, red = still unresolved), the annotated text panel, and two independent audio players (original OCR on top, corrected below) with a font-size control.

gemini-3.1-flash-tts free tier caps at 10 requests/day
Resumable — an already-synthesized .wav in review_audio/ is reused, not redone.

Reminder — the normal reader needs no separate step

src/pipeline/build_reader.py (part of the main pipeline, not tools/) automatically picks up ensemble_review.json if it exists — highlighting flagged/verified words and borrowing Gemini's box+image per page when LightOn has none. Just rebuild it after any of the apply steps above:

.venv/bin/python3 -c "
import sys; sys.path.insert(0,'src')
from pipeline import build_reader
from pathlib import Path
build_reader.build(Path('work/المومياوات ناشيونال جيوجرافيك-lighton'))
"
